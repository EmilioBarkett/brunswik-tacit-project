# German Credit Dataset Decoder

Decodes the German Credit Dataset (german.data) from encoded categorical
values into a human-readable CSV file.

## Files
- `german.data` — raw dataset (1000 rows, 21 attributes)
- `decode_german_credit.py` — decoding script
- `german_credit_decoded.csv` — output (generated by the script)

## How to run
```bash
python decode_german_credit.py
```

## Output
Produces `german_credit_decoded.csv` with plain-English labels for all
categorical attributes and a `credit_risk` column (Good/Bad).

## Corrected Study 2 analysis

### Why this exists — two problems with the original numbers
The German Credit (Study 2) process-alignment cosines reported in the paper were
produced by `analyze_weights.py`, and have two problems. **Problem A (wrong
construct):** `encode_features` builds the regression design matrix from the
LLM's own per-case *tier labels* (HIGH/MEDIUM/LOW, label-encoded), not the actual
case features (which sit unused in the `*_dec` columns), and the "organization"
vector is the ground-truth outcome regressed on those same tier labels,
recomputed per model — so the published cosine never uses the real cue values and
has no fixed organizational policy, which is not the method the paper describes.
**Problem B (non-reproducibility):** under current pandas the tier labels load as
a string dtype, so `encode_features`'s `dtype == object` test fails, routes them
through `pd.to_numeric().fillna(0)`, zeroes the design matrix, and the cosine
becomes NaN — so the committed `analysis/*_balanced.txt` reports no longer
regenerate from HEAD. Problem B is now fixed in `analyze_weights.py` (a
`is_numeric_dtype` check restores the intended behaviour); that legacy tier-label
path is kept **only** to reproduce the originally reported numbers and is
superseded by `calm_corrected/`. (ECHR / Study 1 uses binary cues, is unaffected,
and is not touched here.)

### The corrected method and its construct choices
`calm_corrected/` regresses each LLM's decisions, and the organization's
historical decisions (the `credit_risk` labels), on the **actual cue values** —
one-hot encoded and standardized — in a **shared feature space**, against **one
fixed organizational policy**. The construct choices (flagged for co-author
review, not yet co-author-validated; all are named constants at the top of
`calm_corrected/core.py`) are:

- Coefficients compared in the **one-hot expanded space** (`ONE_HOT_DROP_FIRST=False`).
- **One fixed org policy**, fit once on the **balanced 600** cases (all `Bad` +
  a `random_state=42` sample of `Good`), as a logistic regression of
  `credit_risk` on the cue values.
- Ridge strength **`C = 1.0`**.
- Protected-attribute **"usage" = L2 norm of the unit-normalized coefficients**
  over an attribute's one-hot columns.

The cell→file mapping (which exact results CSV is each model×condition) is
load-bearing and verified against the committed balanced reports; `core` asserts
each loaded file's `model`/`condition` columns match the expected cell and fails
loudly otherwise.

### Headline (read this before citing anything)
The robust finding is the **level** of corrected alignment: it is uniformly near
zero (range ≈ **−0.25 to +0.21**, SD ≈ 0.12; **only 1 of 14 cells exceeds +0.15**;
by-condition corrected means: baseline −0.05, org-ext +0.08, introspective −0.03).
The corrected cosine-vs-accuracy **correlation is not a headline finding** — it is
leverage-driven (Pearson r = **+0.77** over all 14 cells but only **+0.37**
excluding GPT-5.4-nano; n=14 over a narrow range). The scatter figure's fit
annotation deliberately reports **both** the full r and the excluding-GPT-nano r.

### Validation
`calm_corrected/validate.py` re-runs `run_alignment` and asserts the published
anchors (the 14 `repro_cos` values to 3 decimals, the legacy r≈+0.15, and the
corrected-cosine spread/means/correlations). It exits nonzero with a clear
per-check diff on any mismatch. **Known numerical drift:** 12 of 14 `repro_cos`
cells reproduce the committed reports exactly; two boundary cells — Grok 4.1 Fast
[org-ext] and DeepSeek v3.2 [introspective] — compute to **+0.177 / −0.184** on a
numpy≥2 / current-BLAS stack vs the committed **+0.176 / −0.183** (a sub-0.0015
solver/BLAS difference, verified stable across scikit-learn 1.5–1.9; numpy 1.x
does not build on Python 3.13). `analyze_weights.py` post-fix produces the same
two values, so this is library drift, not a method regression. The validator
absorbs it via a documented `REPRO_TOL = 0.0015` while still failing hard on real
regressions (the NaN bug, a sign flip, or the wrong construct all differ by
≥ 0.05). The committed expected values are **not** edited.

### Protected-attribute usage (coefficient-level companion to the paper)
`protected_attribute_usage.{png,csv}` is the **coefficient-level version** of the
paper's tier-based *Protected Attribute Weighting* discussion
(`report/icml2026/calm_pluralistic_alignment.tex`, §"Protected Attribute
Weighting"). Where that subsection reads protected-attribute reliance off the
descriptive tier labels (e.g. Claude rating `foreign_worker` HIGH), this measures
it directly from the fitted policy coefficients. The pattern is consistent: the
organization uses the protected attributes more than the LLMs do (org
age/sex/foreign = 0.19/0.16/0.13 vs LLM-baseline means 0.09/0.08/0.11), and
org-externalization does **not** push the LLMs toward using them — foreign-worker
usage *falls* for 4 of 5 models (Claude 0.15→0.03, GPT-5.4-mini 0.12→0.02,
GPT-5.4-nano 0.08→0.03, DeepSeek 0.13→0.10) and rises for none (Grok flat at
0.08), even as the same intervention raises usage of legitimate cues like
checking account and duration.

### Notebook reconciliation (flag, not resolved)
`main_analysis_balanced_mistral-large.ipynb` is the **ECHR / Study 1** pipeline
(Mistral Large over `dataset_ecthr_cases`, organization = the court decision
`court_decision_6_violated`), **not** a German Credit reimplementation. It shares
the *shape* of `calm_corrected/core` — StandardScaler + ridge logistic
regression, organization = the institution's own historical decisions,
coefficient **cosine similarity** as the primary alignment metric in a shared
cue space — but it **differs** on these points:

1. **Data/study.** ECHR binary coded cues vs German Credit one-hot-expanded cue
   values; the notebook uses `SimpleImputer(strategy="most_frequent")` then
   `StandardScaler`, while `core` fills missing with 0 and has no imputer.
2. **Regularization.** The notebook tunes `C` per fit via
   `LogisticRegressionCV` over `np.logspace(-3, 3, 25)` with nested
   `StratifiedKFold`; `core` uses a **fixed `C = 1.0`** for every fit.
3. **Org policy scope.** The notebook refits the court (org) policy in place and
   per bootstrap resample; `core` fits **one fixed org policy once** on the
   balanced 600 and reuses it for all LLM comparisons.
4. **Estimation.** The notebook uses cross-validated fits (and propensity/CV
   metrics); `core`'s coefficient vectors come from single full-data fits.
5. **Usage metric.** The unit-norm L2 protected-attribute "usage" metric exists
   only in `calm_corrected/`; the notebook has no equivalent.

These are flagged, not reconciled: the notebook is not modified. The shared
cosine metric (`1 - scipy.spatial.distance.cosine`) is mathematically identical
to `core.cosine`.
